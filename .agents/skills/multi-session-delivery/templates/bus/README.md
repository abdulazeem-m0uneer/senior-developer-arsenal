# Session message bus

Durable copy of the messages between the sessions. Copy this folder to `<workspace>/.agents/bus/` and list the session names in `lanes.txt`, one per line (`pm` is always accepted). `lanes.txt`, `.agents/pm/lanes.json` and the lane table in the rules must name the same sessions.

- **Send:** `bash send.sh <to> <from> "<one line>"` appends `<ISO time> | from <sender> | <message>` to `inbox-<to>.md` (newlines become spaces), then send the live message.
- **Receive:** `bash read.sh <me>` prints the lines after your read mark (`read-mark-<me>.txt`, 0 when missing) and leaves the mark where it is. Act on each line, then acknowledge with the command it printed: `bash read.sh <me> --ack <line>` moves the mark to that line. Delivery is at least once: a session that stops before acknowledging sees the same lines again, so a line that arrives while you work is never skipped. If `archive.sh` ran between the read and the acknowledgement, read again first: the line numbers shifted.
- **Never** edit or delete lines by hand. Each week the coordinator runs `bash archive.sh 7`: under the bus lock it moves lines that are older than 7 days and already acknowledged to `archive/` and shifts the read mark. Unacknowledged lines always stay.
- All three scripts share one lock (`.lock`, a file created with an exclusive open, holding the owner's pid, start time and host). It is released on exit, interrupt and termination. A lock left by a killed script is taken over by the next script once its owner's pid is gone, or once it is older than `BUS_LOCK_STALE` seconds (default 60); nothing is removed by hand. A script waits `BUS_LOCK_TRIES` tenths of a second (default 100) and then exits 3. Session names are lowercase letters, digits and hyphens. A lock whose owner was never written (a script killed between creating it and writing it) is aged in whole minutes, so it is taken over only after about 2 minutes with the default; until then senders exit 3.
- **ETA on everything:** `START <key> <what> - ETA [YYYY-MM-DD |MM-DD |MM/DD ]HH:MM` takes an item, `BLOCKER <key> <exact cause> - <who acts> - ETA ...` says it stopped and when it will be solved, `DONE <key> <evidence>` (or `CLEARED`) closes it with the merged commit, green run or check that proves it. `send.sh` runs `send_check.py` first: exit 6 for a `START` or `BLOCKER` without a key or without a valid ETA (the last ETA in the line counts; a time already past today means tomorrow; a month-day takes the year nearest now; not in the past and at most `BUS_ETA_MAX_DAYS` days ahead, default 90), a `DONE` without a key and evidence, a keyword not written in upper case, or a line starting with the old words `started` or `blocked`; exit 7 for a re-date without a cause: a `START` (a `BLOCKER` is never refused for this: its text is the cause) whose key the same sender already has open, with an ETA later than the open item's, and no `because ...` or `cause: ...` followed by at least 3 words (an earlier or equal ETA, a first `START`, another session's key or a reopened item is not a re-date; if `open-items.tsv` or `overdue.py` cannot be read the line is not refused and a note goes to stderr); exit 4 for a weekday that does not match its date (`Wed 11-26` when it is a Thursday; also `Thurs`, `Weds`, `MM/DD`) or a date that does not exist. A key starts with a letter, a digit or `#`. Refused lines are not written. Codes 4 to 19 are reserved for `send_check.py` refusals: `send.sh` passes any of them on as a refusal (event `refused-<n>` for a code it has no name for), so a rule added to the check can never go out as "unchecked"; when you add one, raise `Refused(<n>, ...)` with a free code in that range and add it to both headers. Leading spaces are ignored and a colon after the keyword is allowed. When the check cannot run (no `python3`) or the record cannot be written, the line still goes out once, with a warning.
- **Open items:** each accepted `START`, `BLOCKER` and `DONE` is appended, after its inbox line and under the same lock, to `open-items.tsv`: sent time, sender, key in lower case, ETA (`YYYY-MM-DD HH:MM`, local) or `DONE`, the line. `overdue.py` also reads the short forms people type by hand (`MM-DD HH:MM`, `HH:MM`) against the record's own send time, by the rules `send_check.py` uses, and counts any ETA it still cannot read (`UNREADABLE` in `--accuracy`, `unreadable` in `--health`). An item belongs to the session that opened it: only its own `DONE` closes it, and a later `START` or `BLOCKER` of it is a re-date only when its ETA is later than the one before. `python3 overdue.py` lists open items past their ETA (`--all` also those inside it) with hours open, hours past the first promised ETA, re-dates and `ESCALATE` (re-dated twice, or 4 hours past its first promised ETA; `--escalate-redates`, `--escalate-hours`). `python3 overdue.py --waiting` lists each open `BLOCKER` whose acting session (the last `- <session>` in the line, a name in `lanes.txt`) has no open item for that key. `python3 overdue.py --accuracy` (its "median late" is over the late items only) reports per session how many finished items met their first promised ETA, the median lateness of the late ones, re-dates, and items open past their first ETA. `python3 overdue.py --suggest <session> --estimate 2h [--min-history 3] [--json]` prints the ETA to promise (now + estimate + that session's median lateness over all its finished items against their first ETAs, early or on time counting 0, rounded up to the next quarter hour, as `ETA MM-DD HH:MM`) and how it was derived; with too little history it gives the estimate alone and says so. `BUS_NOW` fixes the clock for tests. The file only grows; never edit it by hand.
- **Events and health:** every `send.sh` attempt adds one line to `events.jsonl` (or `$BUS_EVENTS`): time, sender, receiver and outcome (`sent`, `refused-weekday`, `refused-eta`, `refused-redate`, `refused-<n>`, `unchecked` when the check could not run, `untracked` when the record failed), never the message text. `python3 overdue.py --health [--since 24h]` prints one line: open, overdue and escalated items, sends, refusals, bypasses and damaged lines; it exits 1 (`degraded`) when a line went out unchecked or untracked, a record is damaged or an open item's ETA is unreadable (rewrite it with a new `START` or `BLOCKER`), so the other listings are not trusted blindly. Times in ETAs are 24-hour; write hour ranges as times (`Mon 10:00-12:00`), since `Mon 10-12` reads as a date.
- **No secrets** (tokens, keys, passwords, personal data) in any line.
- Renaming a session: add the new name to `lanes.txt`, test `send.sh` and `read.sh` with it, then update the rules files in the same step.
